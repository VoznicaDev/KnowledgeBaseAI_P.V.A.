# KnowledgeBaseAI
Это система для обучения, представляет собой карту знаний с узлами и связями между ними, чем отличается от обычных курсов, где проходишь урок за уроком. Система позволяет создавать темы, навыки, связи,строить персональные маршруты обучения, диагностировать уровень знаний.
Подойдёт для преподавателей, студентов, школьников, разработчков и компаний. 
# Архитектура
Код разложен по "папочкам" со своими названиями. Есть инструкции как запустить, имеются тесты, проект представляет собой высокий уровень профессионализма с хорошим потенциалом. Ядро проекта находится в папке backend/src т.к. там работа с API и графом, и даже папка core/ имеется.

KnowledgeBaseAI/
├── backend/                 # Серверная часть
│   ├── src/                 # Исходный код
│   │   ├── api/            # REST эндпоинты
│   │   ├── services/        # Бизнес-логика
│   │   ├── db/             # БД (Neo4j, Postgres, Qdrant)
│   │   └── core/           # Конфигурация, безопасность, математические движки
│   └── tests/              # Тесты
├── frontend/               # Веб-интерфейс
├── traefik/                # Конфигурация Traefik
└── docker-compose.yml     # Настройки контейнеров

## Фронтенд - то, что видит пользователь. Интерфейс.
Страница с графом, его редактор и интеллектуальные карты. 
React, TypeScript, Vite.
## Бэкенд - то, что находится "под капотом".
Обрабатывает запросы интерфейса, управляет БД, общается с ИИ.
Python, FastAPI.
## БД - хранилища информации.
Neo4j хранит схему связей и знаний.
PostgreSQL хранит пользователей и найстройки. 
Qdrant помогает ИИ в поиске информации.
## Инфраструктура.
Docker упаковывает всё в контейнеры, чтобы можно было запускать на разных системах, учитывая библиотеки, зависимости, конфиги и тд.
Traefik распределяет запросы между сервисами, так сказать, курирует поток информации и поддерживает стабильность работы всей системы.
Prometheus собирает метрики, чтобы использовать для дальнейшего анализа.

# Запуск.
Запуск описан в файле readme. Нужно в конфиге указать данные, переименовать или создать новый с окончанием .prod, а после запустить docker-compose up -d --build. 
В моём случае возникли сложности с необходимостью настройки. После запуска, через docker не отвечали три контейнера Neo4j, PostgreSQL и Prometheus. Запустить проект полностью не удалось т.к. у меня отсутствовали данные для входа, необходимые в Neo4j и PostgreSQL. 
## Личные выводы.
Архитектура имеет чёткое разделение на бэк и фронт с использованием докера. 
Основная концепция — это использование графа для подстраиваемого обучения.

Мои знания до задания - это пайтон и общее понимание, что такое фронт, бэк, апи, субд. Это моё первое погружение в проект и мне было непонятно буквально всё. Честно говоря, я и сейчас-то мало чего понимаю, но это гораздо больше, чем я знал до этого задания, например — докер. Раньше только слышал что-то про микросервисы. Пришлось смотреть в интернете, подключать друзей,  общаться с ИИ-чатами, задавать вопросы, разбираться в новом для себя мире.
